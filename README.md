# 电量守护 / Battery Guardian

给"经常忘记插电、直到自动关机才想起来"这件事做的 Windows 小工具。

它不试图做"更醒目的提醒"，因为提醒失效的原因不是不够醒目，而是**忽略它的成本为零**。
所以它做的事是：把忽略的代价从 0 抬起来，直到你必须起身插一下。

---

## 六层机制

不是六个并列开关，是**同一条升级链**。电量往下走，压强逐级升高；插上电，全部立刻安静。

| 层 | 触发 | 做什么 |
|---|---|---|
| L1 换触发点 | 50% | 浮条转琥珀色，提示接电。**不弹窗、不打断** |
| L2 常驻浮条 | 一直 | 把电量翻译成"还能撑多久"，不弹窗、不消失 |
| L3 说谎检测 | 20% | 弹确认框，唯一按钮是"已插电"，点下去真的读充电状态 |
| L4 即时代价 | 10% | 屏幕顶部一条横幅，真的占掉你一块屏幕（默认关闭） |
| L5 电费账本 | 双击浮条 | 把"用电池省钱"这笔账算给你看 |
| L6 保底层 | 8% | 60 秒倒计时后自动休眠，让最坏结果不是硬关机 |

**L1 / L2 不主动打断你。** 它们只改浮条的配色和文案（50% 起转琥珀、30% 起写"建议现在接电"），
不会弹任何窗口。真正会跳出来占你注意力的只有 L3 之后的三层——前面越轻，后面才有分量。

**L3 是核心。** 那个按钮不是"我知道了"，而是"我已插电"——点下去会调用
`GetSystemPowerStatus` 校验 AC 状态。没插电，窗口就在；60 秒后它再大一圈。
右上角的 × 也接成了同一个校验，所以没法用 × 糊弄过去。

**L6 为什么是休眠不是关机。** 硬关机到 0% 是深度放电，对锂电池最不友好，而且丢数据；
休眠会把内存写进硬盘再断电，醒来还是原样。两者代价差很远。

## 吸附与收起

浮条可以拖到**屏幕左右边缘**吸附，鼠标移开 1.5 秒后自动收成一条 **6px 彩条**，
鼠标移上去滑出，点一下固定展开、再点一下取消固定。

收起态那条细带的颜色就是状态本身：

- 绿 = 已接电
- 琥珀 = 开始提醒（50% 以下）
- 红 = 正在逼你插（20% 以下）

**但这里有个必须处理的冲突：自动收起和"常驻可见"是打架的。**
常驻浮条的全部价值在于你不需要主动想起它；收起来就回到了"得想起来才看一眼"。

所以规则是：**只在安全档位允许收起，进入警告档位强制滑出并锁住，不允许收。**
默认阈值 `collapse_lock_below = 30`，即 30% 以下永远展开。
这样"碍眼"只在你电量充裕时被解决，该看的时候它一定在。

| 操作 | 行为 |
|---|---|
| 拖到边缘 28px 内松手 | 吸附到该侧，外侧直角、内侧圆角 |
| 拖离边缘 | 解除吸附，恢复四角圆角 |

**固定状态有专门的视觉标识**：边框换成主题色、加粗到 2px，左侧再点一个「书签」小方块。
没有它，悬停展开和固定展开长得一模一样——用户分不清「现在是因为鼠标在上面才展开」
还是「已经钉住了」。这是试用时提的问题，改掉了。
| 鼠标移到收起态附近 | 滑出展开 |
| 鼠标移开 1.5 秒 | 自动收起（安全档位且未固定时） |
| 单击 | 切换"固定展开" |
| 双击 | 打开电费账本 |
| 右键 | 安静 30 分钟 / 1 小时 / 到明早 / 退出 |

## 逃生口

一个点不掉的窗口会变成恶意软件，所以留了三个出口：

- **长按 Esc 1.5 秒** —— 安静 30 分钟（真的没法插电的时候用）
- **右键浮条** —— 安静 30 分钟 / 1 小时 / 到明早
- **改配置** —— 把 `enable_fail_safe` 设为 `false`，保底层就不会动手

**静音只关「打扰」，不关保底层。** 确认框和横幅会消失，但电量跌到 8% 时
休眠倒计时照样起来——静音是"别烦我"，不是"让机器死机"。
另外，电量已经低于 30% 时右键菜单里的「安静到明早」会置灰，因为那个组合基本等于
亲手安排一次硬关机。

## 提示音

只在两个**需要你真的做点什么**的档位响，其余保持安静：

| 时机 | 音色 | 说明 |
|---|---|---|
| L3 确认框弹出 | `SystemExclamation` | 20%，该插电了 |
| L6 休眠倒计时弹出 | `SystemHand` | 8%，更急 |

设计上的三条约束：

- **不到处响。** 到处响等于没响，跟一开始那个被忽略的系统弹窗是同一个道理。
  所以 L1/L2 只改配色和文案，一声不出。
- **异步播放**（`SND_ASYNC`），不阻塞界面；没声卡或非 Windows 时静默跳过，
  提示音是增强，不是依赖。
- **静音挡不住保底层那一声。** 跟 L6 本身不受静音影响保持一致：
  静音是"别烦我"，不是"别提醒我要关机了"。

三个开关：`sound_enabled`（总）、`sound_on_dialog`、`sound_on_failsafe`。

## 开机自启

右键浮条 →「开机自启」，勾上即生效，再点取消。

- 只写 **`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`** 下的
  `BatteryGuardian` 值，**不需要管理员权限**，也不碰 HKLM
- exe 版写的是 exe 路径；源码版写的是 `pythonw.exe + 脚本路径`
  （用 `pythonw` 才不会每次开机闪一个黑框）
- 路径带引号——目录名里有空格也不会断
- 卸载 = 取消勾选 + 删目录，注册表里不留东西
- **演示模式（`--demo`）不写注册表**：截图、调界面不该在系统里留下痕迹
- 写失败会把菜单的勾选状态回滚成真实状态，不让菜单骗人

## 运行方式

### 方式一：源码（推荐自己用）

双击 `启动.bat`，它会自动找一个带 tkinter 的 Python 并启动，找不到会给出提示。

```
pythonw battery_guardian.py
```

### 方式二：exe（推荐发给别人 / 换机器）

双击 `build_exe.bat` 打包，产物在 `dist\BatteryGuardian.exe`，单个文件，**目标机器不需要装 Python**。

## 打包与跨设备可用度

这部分是 exe 最容易翻车的地方，逐条说明。

### 已经处理掉的坑

| 问题 | 处理 |
|---|---|
| 打包后 `__file__` 指向临时解包目录，配置写在那里退出即丢 | 冻结时改用 `%LOCALAPPDATA%\BatteryGuardian\data\` |
| 无控制台时 `--self-test` 等命令输出看不到 | 冻结且为命令行模式时，输出重定向到 `data\cli.log` |
| 图标文件在单文件模式下找不到 | 用 `sys._MEIPASS` 解析资源目录 |
| 打包环境缺 tkinter | `build_exe.bat` 会先探测 `import tkinter` 再建虚拟环境 |

### 跨设备行为

- **目标平台**：Windows 10 / 11 **x64**。ARM64 和 32 位不支持——PyInstaller 打的是本机架构，换架构要重新打。
- **无需 Python**：解释器、tkinter、Tcl/Tk 全部打进 exe。
- **体积**：实测 **8.5 MB**（单文件，Python 3.14 + tkinter）。排除掉不用的 `ssl`/`_hashlib` 等模块后
  从 11.7 MB 降下来，主要是甩掉了 `libcrypto-3.dll`（5 MB）和 `libssl-3.dll`（0.8 MB）。
- **单文件代价**：每次启动会解压到 `%TEMP%\_MEIxxxx`，冷启动约 1–2 秒；`--onedir` 更快但要带一个目录。
- **配置位置**：`%LOCALAPPDATA%\BatteryGuardian\data\`。卸载 = 删 exe + 删这个目录，不留系统痕迹。
- **未签名**：SmartScreen 会提示"未知发布者"，需点"更多信息 → 仍要运行"；部分杀软会对 PyInstaller 单文件误报，加白名单即可。
- **系统能力依赖**：`GetSystemPowerStatus`（所有 Windows 都有）、`SetSuspendState`（休眠需系统开启休眠，失败自动回退 `shutdown /h`）。
- **无电池的台式机**：浮条显示「无电池 · 已接电」，不显示百分比、不显示连续天数。
  （早期版本这里会显示「-1%」——`BatteryLifePercent` 是 BYTE，用有符号字节读会把
  表示"未知"的 255 变成 -1。）
- **高 DPI**：按系统 DPI 自动缩放，125% / 150% / 200% 均可。

### 已知限制

- **只在主屏工作**。`winfo_screenwidth()` 返回主屏尺寸，多显示器下浮条固定在主屏，不会跟到副屏。
- 吸附只做左右两边，上下不支持（横条吸上下排版会变形）。
- 自动收起依赖鼠标位置轮询（120ms 一次），不是系统级 hover 事件。
- **演示模式（`--demo`）可以和正式版同时运行**（互斥名不同），屏幕上是两个独立浮条。
  演示模式**不写任何数据**——`stats.json` / `config.json` 都不落盘，所以截图、调界面
  不会污染真实统计；但两个浮条的数字仍然各算各的，别把演示那个当准。

### 分发建议

`dist/` 在 `.gitignore` 里，**exe 不进仓库**——每次重新打包都会让仓库膨胀 8.5 MB。
推荐做法是把 `BatteryGuardian.exe` 作为 **GitHub Release 附件**发布：

```bash
gh release create v1.1 dist/BatteryGuardian.exe \
  --title "v1.1" --notes "首个版本"
```

如果你更希望 exe 直接躺在仓库里，把 `.gitignore` 里的 `dist/` 删掉即可。

### 验证情况（如实记录）

**实测（本机）**

- 源码运行：浮条四档状态（已接电 / 45% / 15% / 5%）、确认框、休眠倒计时、账本、L4 横幅
- 吸附收起：右吸附 / 左吸附 / 收起 / 展开 / 固定 / 拖离，`selftest_ui.py` **197 项断言**，连续多轮全通过
- 自动收起：启动 5 秒宽限期后，鼠标不在浮条上会自行收成彩条
- exe：`--where` / `--once` / `--self-test` 与 GUI 启动、自动收起、确认框、窗口图标
- **打包流程不碰用户数据**：`selftest_verify.py` 造一个假 app_home 跑一遍 `verify_exe.py`，
  断言 `config.json` / `stats.json` 仍在、真实 `data/` 的 mtime 与文件列表都没变
- **变异验收**：三套脚本（`_mutcheck_round2/3/4.py`）共 43 项「故意改坏」，全部能被测试抓到

**模拟验证（不需要第二台机器）**

- **DPI × 分辨率矩阵**：`selftest_layout.py` 覆盖 12 种组合
  （1366×768 / 1920×1080 / 2560×1440 / 3120×2080 / 3840×2160 / 1280×720 / 1024×768，
  DPI 100% / 125% / 150% / 200% / 250%），检查浮条不越界、贴边无误差、对话框完整可见。
  原理：设置 `tk scaling` 会同时改变 `winfo_fpixels('1i')`，所以 `S` 的推导走的是真实代码路径，
  不是硬塞的假值。
- **陌生机器环境**：把 `LOCALAPPDATA` / `TEMP` / `TMP` 指到空目录、并从另一个工作目录启动 exe，
  确认配置仍正确落在 `%LOCALAPPDATA%\BatteryGuardian`，说明没有硬编码路径、不依赖当前目录。
- **环境变量缺失**：删掉 `LOCALAPPDATA` 后仍能回退到 `USERPROFILE\AppData\Local` 正常启动。

**依赖审计（静态分析，不是实测）**

扫 exe 里的 DLL 引用，只有 5 个系统库（`kernel32` / `user32` / `gdi32` / `advapi32` / `comctl32`），
其余全部打包在内，包括 **`vcruntime140.dll` 和 `ucrtbase.dll`**。

这意味着"目标机器没装 VC++ 运行库"的风险很低——VC 运行时是随 exe 一起走的。
但这是字符串扫描得出的结论，不等于在干净系统上实测过。

**无法模拟（需真机）**

- **ARM64 / 32 位**：PyInstaller 打的是本机架构，无法用软件模拟，必须换机器重打。
- **干净系统首次运行**：需要一台全新 Windows。本机是家庭版，没有 Windows Sandbox，
  也没有第二台机器。依赖审计把风险压低了，但没有替代真机验证。
- **真实多显示器**：需要两块物理屏；代码目前只取主屏尺寸，这一条是已知限制而非待验证项。

开发过程中修掉的九个真实缺陷（记录在案，便于复查）：

1. hover 循环每 120ms 调一次 `collapse()`，而滑动动画需要 135ms，原实现每次都重启动画，
   导致最后一帧永远走不到、`_animating` 卡在 `True`，浮条从此再也收不起来。
   现改为按「目标状态」去重 + 代数接管。
2. `render_hud()` 只在宽度变化时才调 `_sync_geometry()`，宽度不变但屏幕变了（换分辨率、
   插拔外接屏）位置会停在旧值，浮条可能留在屏幕外。现改为无条件重新贴边。
3. 剩余时间单点估值 + 来源不透明 + 允许多开，导致同一时刻两个浮条显示不同数字。
   现在单实例保护 + 双窗口区间 + 系统估值标「系统」+ 量化噪声门槛。
4. 台式机上显示「-1%」：`_SYSTEM_POWER_STATUS` 的字节字段用了有符号类型。
   现已改为无符号，并补了台式机专用的文案与回归用例。
5. **静音会把保底层一起关掉。** `_handle_escalation()` 开头就把静音和 L6 一起短路，
   `mute()` 里还主动关掉倒计时窗口——5% 时点一次「安静到明早」等于亲手保证硬关机。
   现在 L6 排在静音判断之前，`mute()` 只关确认框和横幅。
6. **阈值不做顺序校验。** 只把每个阈值单独夹到 0–100，`fail_safe` 手改成 50 时
   45% 就会落进保底层 → 高电量自动休眠。现在按 hint ≥ nudge ≥ dialog ≥ cost ≥ fail_safe
   逐级夹取，并给 `fail_safe` 加一个**绝对上限**（15%）：级联只保证顺序不保证量级，
   五个阈值整体上调时 `fail_safe` 会被「合法」抬到 48%，那就成了高电量休眠。
7. **打包验证会删掉整个数据目录。** `verify_exe.py` 为了「从干净的 cli.log 开始」，
   对 `%LOCALAPPDATA%\BatteryGuardian\data\cli.log` 做了两次 `dirname` —— 正好是整个
   `BatteryGuardian` 目录，于是每打一次包就把 `config.json` / `stats.json` 一起删掉，
   `ignore_errors=True` 让它完全静默。现在改成把子进程的 `LOCALAPPDATA` 指到临时目录，
   与真实数据物理隔离。
8. **主循环没有异常保护。** `tick()` 最后那句 `after` 是循环唯一的续命动作，任何异常
   跳过它，循环就永久停止——浮条不刷新、确认框不弹、**保底层不触发**，且没有任何提示。
   开机自启让它变成 7×24 长期运行之后，这从理论风险变成迟早发生。
9. **`TclError` 是唯一不重排的分支。** 上一版对 `TclError` 直接 `return`，而它恰好是
   注释里写下的「加这个保护的主要动机」（RDP 重连 / 显示器切换）。现在改成记日志后
   照常重排。真销毁时 `after()` 其实**静默成功、不抛异常**（实测），所以靠连续失败计数兜底，
   到 `TICK_TCL_GIVE_UP` 次之后才彻底放弃重排。
   顺带加了「连续失败 6 次就让浮条改口说『电量读取失败』」——一个还在动但已经瞎了的
   工具，比直接死掉更难被发现。

这些都是自动化测试跑出来的，肉眼点几下发现不了。

## 剩余时间是怎么算的

**优先用 Windows 自己的估算**（`BatteryLifeTime`），格式也跟系统一致：
「约 2 小时 15 分钟」。

为什么不用自研的速率外推——这是实机试用三天后改的：

- **分辨率不对等**：`BatteryLifeTime` 来自电池驱动/固件，读的是 mWh 和秒级放电率；
  我们只能看 `BatteryLifePercent`，那是 0–100 的**整数**
- 短窗口（10 分钟）要掉 2% 才算数，而两个整数端点各有 ±0.5% 的取整误差——
  10 分钟掉 2% 的真实降幅可能是 1%–3%，**速率的不确定度高达 ±50%**
- 两个窗口取 `[min, max]` 当区间，会把两次速率估计的误差叠成区间宽度，
  负载一变区间就炸——那不是抖动，是方法本身的噪声

> 说清楚一点：系统值**也**会随瞬时负载跳，它反映的是"此刻"。
> 它胜出的原因是**分辨率**，不是"更懂你的用法"。

**唯一用自研估算的情况**：刚拔电那几十秒，`BatteryLifeTime` 会返回无效值
（DWORD 全 1）。这时会显示「实测 约 X 小时」，让你知道这个数比系统的粗。

插上电就清空样本，重新开始采集。

**它反映的是「此刻的功耗下还能撑多久」，不是「这台机器还能用多久」。**
同一块电池，写代码和看视频能差三倍——数字突然变化，多半是负载变了，不是估算坏了。

**如果连续 6 次读不到电量**（约 30 秒），浮条会改口显示「电量读取失败」；
如果是界面本身画不出来（显示器切换、RDP 断连），显示的是「**界面刷新失败**」。
两者分开说，因为它们对用户的含义不同：前者该怪电池/驱动，后者只是重绘出了问题。
恢复后会自动回到正常文案，日志里也会记一行「恢复正常」。

如果界面连续 60 次（约 5 分钟）都刷不出来，说明浮条窗口已经被外部销毁了，
程序会停止重试并在日志里写明——不会永远空转。

> 早期版本允许多开，两个实例各算各的速率，屏幕上会出现「43% 约 110 分钟」和
> 「43% 约 172 分钟」两个互相打架的数字。现在加了单实例保护，重复启动只会弹一个提示。

## 电费账本怎么算的

```
每次放电 d%：
  省下的电费 = 电池容量(Wh)/1000 × d/100 × 电价
  电池折损   = d/100 × 深度放电系数 × (换电池价格 / 循环次数)
```

默认假设（可在 `data/config.json` 里改）：

- 电池容量 **自动读取**（`capacity_wh` 还没记录过时，后台跑一次
  `powercfg -batteryreport -xml`，取当前满充容量；读不到才用 60 Wh 这个占位值。
  注意：这个值只在正常退出或拖动浮条时才落盘，所以你如果总是直接关机，
  每次开机都会重读一次——无害，只是别指望它"只读一次"）
- 电价 ¥0.60 / 度
- 换电池 ¥400，设计循环 600 次
- 低于 10% 的部分，折损系数 ×1.5（深度放电更伤）

按默认 60 Wh 算，一次满放电省下约 **¥0.04** 电费，同时消耗约 **¥0.70** 的电池寿命
（其中最后 10% 按 1.5 倍深放电折损计入），**比值大约 1 : 19**。
换成这台机器的实测容量（约 84 Wh，设计 92 Wh——电池在老化，这个数会慢慢变小），
省下的电费变成约 ¥0.05，**比值降到 1 : 14 上下**。

也就是说：**容量越大，账本越"支持"用电池**（因为省下的电更多），
但比值仍然是一个数量级以上的差距，结论不变。

这个数字不是精确值，但量级是可靠的：电池折损比省下的电费贵一个数量级以上。
账本存在的意义不是精确核算，而是把"用电池省钱"这个直觉纠正过来。

### 周对比

账本下半部分还有一块「离电时长」：本周 / 上周各用了多久电池，以及变化百分比。

只算钱是不够的——钱是结果，时长才是你能直接改变的行为。
（时长按两次轮询的间隔累加，单次上限 60 秒，避免休眠醒来把几小时一口气算进去。）

## 顺手该做的一件事

工具只是兜底，系统层面还有一处更硬的保险：

**设置 → 系统 → 电源和电池 → 电池 → 关键电池操作**，改成「休眠」。
默认值通常是「关机」，这正是机器会硬关机的原因。改成休眠，就算所有提醒都失效，
也不会以深度放电收场。

## 配置

`data/config.json`（**首次改动配置时才写出**——比如拖动浮条、点击固定或退出程序；
不动它就一直用内置默认值，文件本身不存在）：

| 键 | 默认 | 说明 |
|---|---|---|
| `thresholds` | 50/30/20/10/8 | 各层的电量触发点 |
| `dock_edge` | `"right"` | 吸附边：`left` / `right` / `null`（不吸附） |
| `pinned` | `false` | 是否固定展开（不自动收起） |
| `collapse_lock_below` | `30` | 低于此电量强制展开，不允许收起 |
| `enable_cost_layer` | `false` | L4 横幅，默认关。它有效但很烦 |
| `enable_fail_safe` | `true` | L6 自动休眠 |
| `sound_enabled` | `true` | 提示音总开关 |
| `sound_on_dialog` | `true` | L3 确认框弹出时响一声 |
| `sound_on_failsafe` | `true` | L6 休眠倒计时弹出时响一声（更急的音色） |
| `fail_safe_countdown` | `60` | 休眠倒计时秒数 |
| `dialog_regrow_seconds` | `60` | 对话框被无视后多久再放大一次 |
| `poll_seconds` | `5` | 电量轮询间隔 |
| `capacity_wh` / `kwh_price` / `battery_price` / `battery_cycles` | 见上 | 账本参数 |

`data/stats.json` 存连续天数、累计放电量、断电事件次数。删掉它就等于重置账本。

## 测试

```bash
# 无界面自检：等级判定、速率估算、容量解析、账本算法、周对比、日志轮转
python battery_guardian.py --self-test

# 界面冒烟测试：吸附 / 收起 / 展开 / 固定 / 拖离 / 提示音 / 主循环韧性
python selftest_ui.py

# 布局矩阵：12 种屏幕尺寸 × DPI 组合，检查越界与贴边精度
python selftest_layout.py

# 打包验证的数据安全：verify_exe.py 不得碰真实 data/（会真跑一次 exe）
python selftest_verify.py
```

前三个脚本都会把配置写到临时目录，不会碰你真实的 `data/`。
`selftest_verify.py` 更进一步：它连子进程的 `LOCALAPPDATA` 都指向临时目录，
并反向断言真实 `data/` 的 mtime 与文件列表没变。

调试用的参数：

| 命令 | 作用 |
|---|---|
| `--demo 15` | 用假电量预览界面，不动真实电源，也不会真休眠 |
| `--panel ledger` | 直接打开电费账本 |
| `--panel failsafe` | 直接打开休眠倒计时。**会强制进入演示模式，不会真的休眠** |
| `--panel about` | 直接打开「关于」窗口 |
| `--once` | 打印一次电池状态就退出 |
| `--where` | 打印配置与资源路径（排查 exe 用） |
